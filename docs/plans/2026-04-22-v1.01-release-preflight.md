# v1.01 发布前补充清单

## 已纳入本次发布基线

1. 字典采用代码内置配置作为权威源，通过 `/api/dictionary/sync` 同步到数据库，新环境无需手工逐项重配。
2. `src/db/seed.ts` 默认仅初始化系统基础数据，不再默认写入客户、项目、方案、任务、预警历史、绩效等业务示例数据。
3. 首发版本发布声明已落库，作为 `v1.01` 的对外说明底稿。

## 发布前仍应补齐的事项

1. 创建发布分支：建议命名为 `release/1.01`，从当前最新稳定提交切出。
2. 生成发布 tag：建议使用 `v1.01`；如需要兼容语义化版本，可同时在文档中标注内部构建版本 `1.0.1`。
3. 确认新环境初始化流程：空库建表 -> 运行迁移 -> 执行 `seed.ts` -> 执行 `/api/dictionary/sync`。
4. 准备首个超级管理员口令：通过环境变量 `SEED_INITIAL_PASSWORD` 注入，避免随机口令不可追踪。
5. 做一次发布验证：至少执行类型检查、关键 API 测试、生产构建、登录与字典加载冒烟。
6. 确认回滚点：保留本次发布 tag、数据库备份、部署前构建产物指纹。

## 不建议作为本次发布目标的做法

1. 不建议把整套业务字典塞进环境变量。环境变量适合密钥和环境差异，不适合维护几十上百项业务枚举；当前“代码配置 + 同步入库”更稳定，也更可审计。
2. 不建议把旧环境业务库整库导入新环境，否则会把客户、项目、消息、工作台痕迹一起带过去，违背首发基线。
